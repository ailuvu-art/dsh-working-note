# DSH Working Note — Technical Specification

> **Status:** Frozen after mockup review — implementation planning lives in [PLAN.md](PLAN.md), exact wire/service contracts in [CONTRACTS.md](CONTRACTS.md), interactive preview in [mockup.html](mockup.html).
> **Target:** DeepSeek Harness (DSH) Web GUI & Host Runtime  
> **Bundle:** `dsh-working-note`, installed by link into the current profile from wherever this checkout lives.

---

## 1. Problem Statement & Objectives

During long-running coding and debugging sessions in DeepSeek Harness (DSH), critical operational context quickly scrolls out of view in the chat transcript:

1. **Workspace / Worktree context:** Which Git worktree or branch the session is currently operating in, and how much code has been added/deleted.
2. **Active test servers & ports:** Which local ports were opened by background jobs or session terminals during manual testing/debugging, with a fast way to inspect and terminate all of them when work is complete.
3. **Human hands-on steps & working notes:** Step-by-step manual instructions generated by the AI agent (e.g., QA steps, manual browser checks) or highlighted directly by the user from chat messages so they never get lost as conversation continues.

### What the approved mockup settled

[`mockup.html`](mockup.html) was reviewed and approved as the interaction reference. These decisions are now binding for implementation:

1. **One compact row, not a card.** The strip is a single 36 px row in `conversation.input.dock`: git/worktree pill · port chips · `Kill all` · steps pill · expand · pop-out. Everything else lives in the disclosed drawer or the right-sidebar tab.
2. **Two-key destructive action.** `Kill all` arms on the first press (`⚠ Confirm kill?`, 3 s) and executes on the second — the same gesture shipped in `ui-jobs`' stop control.
3. **Port rows survive as history.** A stopped port is kept with `state: 'stopped'` (muted dot) instead of disappearing, so a crashed dev server stays explainable; `Clear stopped` and a TTL bound the list.
4. **Bulk entry is a textarea.** Adding steps accepts a multi-line paste and strips `1.`/`-`/`*`/`[ ]` prefixes; duplicates are skipped rather than duplicated.
5. **Origin is visible per step.** Rows added by the model carry an `ai` tag, rows pinned by the user carry a `you` tag, so `set_steps` hygiene is auditable at a glance.
6. **The pin strip must not steal the transcript.** The disclosed drawer is height-capped and scrolls; step text clamps to two lines. (Discovered by hitting the bug in the mockup: a long checklist squeezed the transcript until the text selection under the floating toolbar was unreachable.)
7. **Selection offers both actions.** Highlighting chat text shows `Quote | 📌 Pin note | ⌄`; the overflow menu offers *split into steps* for multi-line/checklist selections. The fallback (`contextmenu`, `Alt+Shift+P`) stays available on an unmodified DSH runtime.
8. **The tab floats.** Right-sidebar "Working Note" tab keeps its `keepMounted` body so it can ride in a floating Dockkit panel while manual testing.

### Core Objectives

- **Always visible, low noise:** Pin key session operational state directly in the session workspace without cluttering the chat flow.
- **Persist & sync across devices:** Store all working notes, UI collapse state, and tracked session ports on the **DSH Host** (`storageDomain`), synchronized in real time across all connected browsers/devices via authenticated SSE. Never rely on browser-local `localStorage` for domain state.
- **Automatic cleanup following Session lifecycle:** Stop active session ports and purge persisted working-note state when a session is archived (respecting DSH's unarchive grace window) or deleted, while keeping state intact across page reloads, host restarts, and in-memory idle session disposals.
- **DSH best-practice compliance:** Use `ctx.storageDomain`, `ctx.jobs`, `ctx.terminals`, `ctx.workingDirectory`, `ctx.systemPrompt`, `ctx.webServer` + `ctx.connection`, `ctx.slots`, `ctx.sidebarRightTabs`, `ctx.locale`, and `--dsw-alias-*` theme tokens. Never write custom events into the core Session event log.

## 2. Non-Goals

- Replacing DSH's `todo_write` tool (which remains the AI agent's internal task planner) or `forge-bundle` (full PR/code-review workflows).
- Tracking or killing arbitrary system-wide services unrelated to the session (e.g., DSH itself, global databases).
- Synchronizing across completely separate DSH Host instances (cross-device sync assumes multiple clients/browsers connecting to the same DSH Host).
- **Windows / macOS port discovery in v1.** Socket ownership is read from Linux `/proc` and `ss`; see §9.7 for the explicit fallback behaviour elsewhere.
- Pinned notes travelling through the model context for **subagents** (v1 keeps them on the session that owns the steps; see §9.8).

The feature is packaged as a DSH bundle (`dsh-working-note`) with a **Host plugin**, an **Agent tool**, and a **Client UI plugin**, plus a small, additive **Core UI extension** in `deepseek-harness` for inline text-selection actions.

### Design Rule: Shared Host Operation Ownership

Following DSH's `user-actions` practice, every state mutation (adding/toggling/editing/removing steps, refreshing git/ports, killing ports) is implemented once as a method on `WorkingNoteService`. Both the HTTP endpoints (called by the UI) and the `working_note` Agent Tool (called by the model) invoke those exact same service methods.

## 4. Data Model & Cross-Device Persistence

### 4.1 Host Storage Domain

Opened via `ctx.storageDomain.open(workingNoteDomainSpec)` with:
- `name`: `'dsh_working_note'`
- `version`: `1`
- `layout`: `'per-record'` (isolates I/O per session record and prevents whole-file rewrites)

Table `sessions` (keyed by `SessionId`):

```ts
import { z } from 'zod'

export const WorkingStepSchema = z.object({
  id: z.string(),
  text: z.string().min(1).max(2000),
  done: z.boolean(),
  source: z.enum(['user', 'ai']),
  createdAt: z.number().int(),
  updatedAt: z.number().int(),
})

export const TrackedPortSchema = z.object({
  port: z.number().int().min(1).max(65535),
  protocol: z.enum(['tcp', 'tcp6']),
  host: z.string(),                  // e.g. '127.0.0.1', '0.0.0.0', '::'
  pid: z.number().int().positive(),
  pgid: z.number().int().positive().optional(),
  processName: z.string(),           // e.g. 'node', 'vite', 'python3'
  command: z.string(),               // bounded command preview (<= 240 chars)
  origin: z.enum(['job', 'terminal', 'worktree']),
  jobId: z.string().optional(),
  terminalId: z.string().optional(),
  state: z.enum(['listening', 'stopped']),
  firstSeenAt: z.number().int(),
  lastSeenAt: z.number().int(),
  stoppedAt: z.number().int().optional(),
})

export const GitSnapshotSchema = z.object({
  cwd: z.string(),
  isGitRepo: z.boolean(),
  isWorktree: z.boolean(),
  repoRoot: z.string().optional(),
  worktreeName: z.string().optional(), // basename of worktree or branch
  branch: z.string().optional(),       // branch name or 'HEAD@<shortSha>'
  baseRef: z.string().optional(),      // e.g. 'origin/main' or 'main'
  uncommitted: z.object({
    added: z.number().int().nonnegative(),
    deleted: z.number().int().nonnegative(),
    files: z.number().int().nonnegative(),
  }),
  branchDelta: z.object({
    added: z.number().int().nonnegative(),
    deleted: z.number().int().nonnegative(),
    files: z.number().int().nonnegative(),
  }).optional(),
  updatedAt: z.number().int(),
})

export const SessionWorkingNoteRecordSchema = z.object({
  sessionId: z.string(),
  steps: z.array(WorkingStepSchema).max(200),
  ports: z.array(TrackedPortSchema).max(100),
  git: GitSnapshotSchema.optional(),
  ui: z.object({
    expanded: z.boolean().default(false),
    gitScope: z.enum(['uncommitted', 'branch']).default('uncommitted'),
  }),
  archivedAt: z.number().int().optional(),
  updatedAt: z.number().int(),
})
```

### 4.2 Why Ports Persist Too

1. **Cross-device visibility:** When a dev server starts on the Host in a session, opening DSH from another browser or phone immediately shows the active ports (and previously seen ports that stopped unexpectedly) alongside live status.
2. **Crash/Restart awareness:** If a background server stops or crashes, the port entry transitions to `state: 'stopped'` (retained briefly or until cleared/dismissed) rather than silently vanishing before the user notices why `localhost:3000` stopped responding.
3. **Kill verification:** On Host startup or client attach, live port verification checks actual OS sockets (`/proc` + `ss`) and reconciles stale `listening` rows to `stopped` (or prunes old `stopped` rows after a configurable TTL, e.g. 10 minutes, or when the user clicks "Clear stopped").

## 5. Session Lifecycle & Cleanup Specification

A critical distinction in DSH: **`session/disposed` / `agent/disposed` is an in-memory idle eviction**, NOT session deletion. Data must survive `session/disposed` and Host restarts, and clean up only when the session is archived or deleted.

### 5.1 Live Session Events
- `session/created` / `agent/created`: Start/attach lightweight session watcher (Git + Port monitor) only while the session has active SSE subscribers or active jobs/terminals.
- `session/disposed` / `agent/disposed`: Release in-memory timers and watchers for that session. **Do not** delete the `storageDomain` record.

### 5.2 Archive & Deletion Cleanup
1. **`workspace/session-activity` (waterfall):**
   - If the session still has **live listening ports** whose origin is `terminal` or `worktree` (note: `job` origin is already reported by `ctx.jobs`), prepend a `SessionActivity` entry (`kind: 'workingNotePorts'`, listing active ports like `:3000 (node)`).
   - If the user archives without `stopActivity`, DSH refuses archival cleanly and warns about open ports.
2. **`workspace/session-stop` (parallel, runs when archiving with `stopActivity: true`):**
   - Execute `killAllSessionPorts(sessionId, { reason: 'session archived' })`:
     - Kill associated `ctx.jobs` entries.
     - Terminate terminal/worktree listening processes (`SIGTERM` -> wait up to `killGraceMs` -> `SIGKILL`), strictly excluding Host PID/PGID.
3. **`workspace/session-archived` (parallel):**
   - Stop any remaining port polling/SSE streams for `sessionId`.
   - Record `archivedAt = Date.now()` and mark all ports `stopped`.
   - Schedule record deletion from `storageDomain` after `archiveGraceMs` (default `30_000` ms) to preserve DSH's immediate **Undo Archive** UX.
4. **`workspace/session-unarchiving` (parallel):**
   - Cancel any pending deletion timer for `sessionId` and clear `archivedAt` so all pinned steps and history remain intact if the user clicks Undo.
5. **Startup & Periodic Reconciliation:**
   - On plugin init (when `sessionQuery` / `sessionPersistence` and `workspaceRegistry` are available), verify every record in `dsh_working_note`:
     - If the session no longer exists in persistence, or was archived longer than `archiveGraceMs` ago, purge its record immediately.
     - Re-verify any `listening` port records against live OS sockets; transition dead PIDs/ports to `stopped`.

## 6. Feature Pillar Specifications

### 6.1 Pillar 1 — Worktree & Git Delta Tracker

- **Source directory:** `ctx.workingDirectory.get(session)` (fallback to `session.header.cwd`).
- **Execution:** `ctx.subprocess.spawn` running `git` with strict argv arrays (no shell interpolation), `timeoutMs: 5_000`, `maxOutputBytes: 1_048_576`, and `GIT_OPTIONAL_LOCKS=0`.
- **Collected fields:**
  1. `isWorktree`: Compare canonicalized `git rev-parse --git-dir` vs `git rev-parse --git-common-dir`. Different paths = linked worktree (`true`).
  2. `worktreeName`: If `isWorktree`, basename of top-level checkout (or branch name); otherwise `repoRoot` basename.
  3. `branch`: `git symbolic-ref --short HEAD` (fallback `git rev-parse --short HEAD` prefixed with `HEAD@`).
  4. **Uncommitted delta (`uncommitted`):**
     - `git diff --numstat -z HEAD` (covers both staged and unstaged tracked modifications).
     - Plus line counts of untracked non-binary files (`git ls-files --others --exclude-standard -z`, bounded by `maxUntrackedFiles: 200` and `maxFileBytes: 512 KiB`, skipping files with NUL bytes in first 8 KiB).
  5. **Branch delta (`branchDelta`, optional/cached):**
     - Resolve base ref: worktree's recorded `baseCommit` (if present in `worktree` projection or git config) or `git merge-base HEAD <defaultRemoteHead>` (`origin/HEAD`, `main`, `master`).
     - Compute `git diff --numstat -z <mergeBase>` (working tree vs merge-base, plus untracked files).
- **Refresh Triggers:**
  - `working-directory/change` (immediate)
  - `tools/result` for file-mutating or shell tools (`write`, `edit`, `apply_patch`, `bash`, `create_worktree`, etc., debounced `800ms`)
  - Manual refresh action from UI
  - Lightweight interval (`10s`) only while an SSE client is actively viewing the session.

### 6.2 Pillar 2 — Session Port Monitor & Safe "Kill All"

#### A. Attribution Strategy (Linux / POSIX)
A port is attributed to `sessionId` if its owning socket PID matches any of these three tiers (highest confidence first):

1. **`terminal` origin (Exact):**
   - Read active terminals from `ctx.terminals.list(agent)` (or `terminalController`) which expose `pid`.
   - Build the full descendant PID tree from `/proc/<pid>/stat` (PPID graph). Any listening socket owned by the terminal PID or any descendant belongs to this session.
2. **`job` origin (Exact via `DSH_SESSION_ID`):**
   - DSH's `shell-env` injects `DSH_SESSION_ID=<sessionId>` into every foreground and background shell tool execution.
   - Scan `/proc/<pid>/environ` (restricted to processes owned by the current OS UID, bounded and read safely ignoring `ENOENT`/`EACCES`) to identify processes carrying `DSH_SESSION_ID=<sessionId>`.
   - Include all descendants of those PIDs.
   - Correlate with `ctx.jobs.list(sessionId)` so job-backed servers retain their `jobId` and `label`.
3. **`worktree` origin (Scoped fallback, configurable `scanWorktreeCwd: true`):**
   - **Only when the session is inside a dedicated Git worktree** (`.agents/worktrees/...` or `isWorktree === true`), or when `scanWorkspaceCwd` is explicitly enabled:
   - Match listening processes whose `/proc/<pid>/cwd` is equal to or a subdirectory of the session's `worktree` path.
   - Rationale: A worktree path is unique to that session, so even if the user starts a dev server in an external IDE terminal inside that worktree, it is safely discovered without colliding with other sessions!

#### B. Socket Discovery (Linux)
- Prefer `ss -H -lptn` via `ctx.subprocess.spawn` (or `/proc/net/tcp` + `/proc/net/tcp6` + `/proc/<pid>/fd` fallback if `ss` is unavailable).
- Parse local IP, listening port, PID, process name (`comm`), and bounded cmdline (`/proc/<pid>/cmdline`).
- **Self-Protection Blacklist (Non-negotiable):**
  - Never attribute or allow killing:
    - `process.pid` (DSH Host process) or any ancestor PID of `process.pid`
    - `process.ppid`
    - Any PID belonging to another `DSH_SESSION_ID`
    - System PIDs (`pid <= 1`)

#### C. Kill Semantics
- **Kill Single Port (`killPort(sessionId, port, pid)`):**
  1. Re-verify PID attribution & self-protection blacklist right before signaling (guard against PID reuse!).
  2. If tied to a live `jobId`, call `ctx.jobs.kill(jobId, sessionId, 'killed by user via Working Note')`.
  3. Send `SIGTERM` to `-pgid` (if process group differs from Host PGID) or `pid`.
  4. Poll for exit up to `killGraceMs` (default `1500ms`); if still alive and still matching process start time/identity, send `SIGKILL`.
  5. Mark port `stopped` (or remove if confirmed dead), persist to `storageDomain`, and broadcast SSE update.
- **Kill All (`killAllPorts(sessionId)`):**
  - Stops all `listening` ports attributed to `sessionId` concurrently.
  - Also kills any remaining running `ctx.jobs` for `sessionId` that are marked as server/background commands if requested, or strictly targets all port-holding jobs + processes.
  - Returns a structured summary `{ killed: [...], alreadyStopped: [...], failed: [...] }`.
  - **UI Safety:** Two-click confirmation on the button (`Kill all (3)` -> click -> `Confirm kill?` active for 3 seconds -> click to execute).

### 6.3 Pillar 3 — Working Steps & Notes

#### A. Step Operations
Every step has: `{ id, text, done, source: 'user' | 'ai', createdAt, updatedAt }`.
- **Add single or batch:** Supports adding one step or splitting multi-line text (stripping leading `1. `, `- `, `* `, `[ ] ` bullets when user chooses "Split into steps" or when AI passes an array).
- **Toggle done / undone**
- **Edit text inline**
- **Reorder** (move up/down or reorder list)
- **Delete individual step / Clear completed steps**

#### B. AI Agent Tool: `working_note`
Registered on `ctx.tools` (following `tool-design.md`: concise description, strict parameter docs, bounded output):

- **Actions:**
  - `list`: Read current session steps, active ports, and git worktree summary.
  - `add_steps`: Append one or more hands-on steps (`steps: string[]`, `dedupe?: boolean`).
  - `set_steps`: Replace all steps (or only AI-authored steps if `preserveUserSteps: true`, default `true` so AI never accidentally wipes user-highlighted notes!).
  - `toggle_step`: Mark a step `done` / `undone` by `stepId` or `index`.
  - `remove_step`: Remove a step by `stepId`.
  - `clear_done`: Remove all completed steps.
- **Safety:** Never wipes user-pinned (`source: 'user'`) notes on `set_steps` unless explicitly requested or individually removed.

#### C. AI Context Injection (`ctx.systemPrompt.context`)
- When `config.injectContextToModel` is enabled (default `true`) and the session has at least one **incomplete step** or **listening port**:
  - Inject a compact, deterministic context block (sorted stably to minimize KV-cache churn when unchanged):
    ```text
    [Pinned Working Note]
    Worktree: <branch> (<path>)
    Open ports: :3000 (node), :5173 (vite)
    Steps:
    - [x] 1. Start local backend
    - [ ] 2. Open /login and test OAuth callback
    ```
  - This ensures that even after 20+ turns or compaction, the AI stays aware of what hands-on steps remain and which test ports are live.

#### D. Highlight-to-Pin (User Selection in Chat)

To make "highlight text in chat -> Pin as step/note" seamless:

1. **Primary UX (Minimal Additive Extension in DSH Core):**
   - Extend `ui-chat` / `message-quotes` with an additive list slot `conversation.chat.text-interaction.actions` inside the floating selection bar.
   - When the user highlights any text in Chat, the floating pill displays:
     `[Quote]` `| [📌 Pin note]` (or dropdown if multi-line: `Pin as 1 note` / `Split into N steps`).
   - Clicking `Pin note` sends the selected text to `POST /api/working-note/steps`, flashes a subtle confirmation toast/highlight on the pin strip, and clears the selection.
   - *(Note: Changes to `packages/client/*` require rebuilding DSH web artifacts and refreshing the browser.)*
2. **Fallback UX (Zero Core Dependency, Built Into Bundle):**
   - Register a `contextmenu` handler on `ctx.uiConversation.interactions` (so right-clicking selected text in Chat also offers `Pin to Working Note`), **plus** a keyboard shortcut (`Alt+Shift+P` when text is selected in `[data-chat-flow]`).
   - This guarantees the feature works even if the bundle is installed on an unmodified DSH runtime.

## 8. Host HTTP + SSE API & Configuration

### 8.1 Authentication & Security
Every route registered on `ctx.webServer` MUST check `ctx.connection.requestRejection(req)` first and reject unauthorized requests (`401`/`403`) immediately. All `sessionId` parameters are validated against `sessionQuery` / `sessionPersistence`.

### 8.2 Endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/working-note/stream?sessionId=<id>` | **SSE stream:** pushes initial full `SessionWorkingNoteView` and incremental updates whenever `steps`, `ports`, `git`, or `ui` change (triggered by tool calls, git changes, port scans, or mutations from another device). Heartbeat comment every 15 s; the stream closes its subscriber on plugin dispose or client abort. |
| `GET` | `/api/working-note/state?sessionId=<id>` | One-shot read of current session working note state. |
| `POST` | `/api/working-note/refresh` | Force immediate Git + Port rescan (`{ sessionId }`). |
| `POST` | `/api/working-note/steps` | Add step(s) (`{ sessionId, steps: string[], source?: 'user' }`). |
| `PATCH` | `/api/working-note/steps/:stepId` | Update `text`, `done`, or position (`{ sessionId, text?, done?, move? }`). |
| `DELETE` | `/api/working-note/steps/:stepId` | Delete a step (`?sessionId=<id>`) or `?clearDone=true`. |
| `POST` | `/api/working-note/ports/kill` | Kill one port (`{ sessionId, port, pid }`). |
| `POST` | `/api/working-note/ports/kill-all` | Kill all listening ports for `{ sessionId }`. |
| `DELETE` | `/api/working-note/ports/stopped` | Clear stopped port history (`?sessionId=<id>`). |
| `PATCH` | `/api/working-note/ui` | Persist cross-device UI state (`{ sessionId, expanded?, gitScope? }`). |

Canonical request/response shapes, status codes, and error codes are fixed in [CONTRACTS.md](CONTRACTS.md) §2; this table names intent only.

### 8.3 Plugin Configuration (`Schemastery`)

```ts
export interface Config {
  portPollIntervalMs: number        // default: 4000 (while SSE subscriber active)
  gitTimeoutMs: number              // default: 5000
  killGraceMs: number               // default: 1500 (SIGTERM -> SIGKILL)
  archiveGraceMs: number            // default: 30000 (undo window before purge)
  stoppedPortTtlMs: number          // default: 600000 (10 min auto-prune for dead ports)
  scanWorktreeCwd: boolean          // default: true (attribute processes whose cwd is in session worktree)
  injectContextToModel: boolean     // default: true (sync steps & open ports via systemPrompt.context)
  maxStepsPerSession: number        // default: 200
}
```

Every field is a Schemastery entry with the JSDoc the user reads in **Settings → Plugins**, and the plugin's `cordis.patch.yml` row ships these defaults explicitly so the profile patch layer is the single place a user edits them (survives bundle upgrades).

## 9. Edge Cases & Reliability

1. **Non-Git directory:** Git section gracefully shows the folder name (or hides diff badge) without errors.
2. **Detached HEAD or unborn repo (no commits yet):** `git diff --numstat HEAD` fails when `HEAD` doesn't exist; fall back cleanly to `git diff --cached --numstat` + untracked files count.
3. **Subagent sessions:** Subagent sessions share or inherit parent workspace; port scanning scopes strictly to the calling `sessionId` (`DSH_SESSION_ID` + own terminals), and Pin Strip hides or marks read-only on non-continuable subagent views.
4. **PID reuse before Kill:** Always validate `/proc/<pid>/stat` start time or command match before sending `SIGTERM`/`SIGKILL` so an already-exited PID reused by the OS is never killed.
5. **Multiple browser tabs / devices open simultaneously:** SSE broadcasts from Host `WorkingNoteService` keep every open device synchronized within milliseconds; `storageDomain`'s single per-domain write chain prevents concurrent write corruption.
6. **Sandbox compatibility:** Git subprocesses use `ctx.subprocess` respecting session limits; if `/proc` read is denied for another user's PID, silently skip that PID (`EACCES`/`ENOENT`).

### 9.7 Portability: port discovery outside Linux

Socket ownership comes from Linux `/proc/net/tcp*`, `/proc/<pid>/fd`, and `ss`. Elsewhere the plugin degrades rather than guesses:

- **macOS:** the *job* and *terminal* tiers still work when `lsof` is present (`-iTCP -sTCP:LISTEN -Fpc`, parsed defensively); the worktree-`cwd` tier is unavailable. When `lsof` is missing, the ports section shows a one-line explanation instead of an empty list — never a silent "no ports".
- **Windows:** port discovery is **off**; the ports section renders the same explanation (`discoveryUnsupported`) and `Kill all` stays disabled. Steps and git behaviour are unaffected.
- The UI reports which tiers are active so a user never mistakes "not discovered" for "nothing is listening".
- A B-tier integration test (§11.3) pins the Linux parser; macOS `lsof` parsing gets its own unit fixture taken from a real machine.

### 9.8 Pinned steps and the model context

- Context is contributed **only for the session that owns steps** — a subagent session has its own `storageDomain` record and sees its own (usually empty) steps, never the parent's. Rationale: steps are human hands-on instructions addressed to one session's user; broadcasting them into delegated work inflates every subagent prompt.
- The contribution lives on the **agent's scope** (`agent.ctx` from `agent/created`), like `working-directory` and `sandbox-policy`, so it disappears with that agent instead of leaking into a sibling composition.
- To stop a disposed agent emitting context, `session/disposed` calls `workingNote.disposeSession(sessionId)`: timers stop, subscribers drop, and the projection handle is released. Any other session can re-create the handle lazily from the persisted record.
- Context text is rebuilt per assembly from current state and includes an explicit "this is pinned hands-on state" frame, so it does not read like a new user instruction. It is `interpolate: false` (no `{variable}` expansion of step text).

### 9.9 Cleanup follows the *session*, not the device

Requirement: *"clean up follow session"*. Because state lives on the Host, one device's archive cleans up for every device at once:

| DSH event | Working Note reaction |
|---|---|
| `session/disposed` (idle eviction) | Release in-memory watchers only. **Record survives.** |
| `workspace/session-activity` | Report port-holing terminals/worktree processes so an archive without `stopActivity` is refused with a clear reason. |
| `workspace/session-stop` | Kill this session's ports (jobs through `ctx.jobs.kill`, processes through the guarded signal path). |
| `workspace/session-archived` | Mark `archivedAt`, stop scanning, broadcast `archived: true` so every open device flips the tab to read-only ("Archived — data is kept for the undo window"). |
| `workspace/session-unarchiving` | Cancel the pending purge, clear `archivedAt`, resume scanning, broadcast read-only off. |
| purge timer (`archiveGraceMs`) | Delete the `storageDomain` record; broadcast `archived: 'purged'` so open views show an empty note rather than stale data. |
| plugin start | Reconcile stored records against `sessionQuery`/`sessionPersistence` + `workspaceRegistry`; purge orphans and expired archives, demote dead `listening` rows to `stopped`. |

A read-only archived view must not offer mutations: the UI hides add/toggle/kill and the Host rejects mutations for a record with `archivedAt` set.

### 11.2 B-tier — Host integration (`node --test tests/host/*.test.mjs`)
Boots the shipped Host composition with `node --experimental-strip-types` and **no profile or web server**, then exercises the service directly through its Cordis context:

- `git.test.mjs` — temp repo with a real commit + a linked worktree: `isWorktree`, `branch`, uncommitted vs branch deltas after an edit.
- `ports.test.mjs` — spawn `node -e "require('http').createServer().listen(0)"` **with `DSH_SESSION_ID=<test>` in its env**; assert discovery with `origin: 'job'`; assert a host-owned listener is never reported.
- `kill.test.mjs` — `killAllPorts` terminates the spawned server (SIGTERM path, and SIGKILL escalation when the child ignores TERM) and leaves an unrelated listener alive.
- `lifecycle.test.mjs` — dispatch `workspace/session-activity` (expect the ports entry), `workspace/session-stop` (ports die), `workspace/session-archived` → `unarchiving` (record kept) and archived → grace elapsed (record purged); `session/disposed` keeps the record.
- `http.test.mjs` — every route rejects an unauthenticated request (401/403), and `state`/`steps` round-trip through the persistent provider.
- `tool.test.mjs` — `working_note` tool: `add_steps` with dedupe, `set_steps` without `preserve_user`, `toggle_step` by id/index, and the resulting context text.

### 11.3 C-tier — live GUI (post-install, manual + inspection)
1. Cross-device persistence: add steps in the GUI, reload → still there; inspect the record via `cordis_inspect`/Host logs.
